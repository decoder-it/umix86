Two kinds of terminal

terminalhow to reach it
CGA console, slot 0the PC screen/keyboard; always present; console-only commands
serial sessions, slots 1..10the bridge's --listen port, a telnet-style TCP connection, or a real serial line

Starting a serial session

python3 tools/serial_mux.py --serial /dev/ttyUSB0 --baud 9600 \
    --listen 127.0.0.1:2323 --http-listen 127.0.0.1:8080
telnet 127.0.0.1 2323

Each TCP client becomes a framed MUX terminal (app 1, termid 1..10). The guest shows USERID:; log in, then the shell prompt is *.

Users and privilege

Accounts live in the users table; USER/USER is the ordinary account and SYSTEM/SYS1 the privileged one (change them). The console always has every command. A serial user gets console-only commands after PRIV ON; PRIV itself can only be turned on from the console.

Shell

Files: DIR TYPE COPY DEL REN EDIT. Programs: RUN BASIC JCL. System: WHO USERS PS MEM SPEED API WEB TFTP CHAT DRIVE BAUD CLS HELP BYE. PS prints slot, name, app, terminal, user, console, state and segment; /WHO inside CHAT lists terminal and web nicknames.

Screen handling

The editor and the chat panel use an 80x25 screen with a pager. Output is line-buffered; long output pages with a key prompt. The console can switch between CGA and Hercules-style text. Baud is set with BAUD (default 9600); the bridge paces input to match.

Notes

  • One request/connection at a time; web and terminal sessions share the same ten serial slots.
  • BYE logs out and frees the slot; the guest sends CLOSE.
  • Keep the bridge on a trusted network: the API and chat are unauthenticated, and the console has no login.
